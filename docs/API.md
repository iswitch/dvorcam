# Адреса потоков и архива

Все адреса ниже отсчитываются от `PUBLIC_URL`. Видео, снимки и архив доступны без авторизации. Админка требует логин и пароль.

## Адреса

| Путь | Что возвращает |
| --- | --- |
| `/<id>-hd/whep`, `/<id>-sd/whep` | WebRTC через WHEP, без перекодирования |
| `/<id>-hd/`, `/<id>-sd/` | Встроенный WebRTC-плеер MediaMTX |
| `/<id>-hd.jpg/`, `/<id>-sd.jpg/` | Свежий JPG или последний сохранённый кадр; 404, если кадра ещё нет |
| `/<id>-hd.jpg/status/`, `/<id>-sd.jpg/status/` | Состояние JPG и время последнего доступного кадра |
| `/archive/<id>/` | Список записей и данные для таймлайна |
| `/archive/<id>/video/?segment=<segment_id>` | Готовый MP4 с поддержкой GET, HEAD и Range |
| `/archive/<id>/preview/?time=<unix_seconds>` | Готовое превью шириной 240 пикселей, высота по пропорциям потока; шаг 15 секунд |

ID относится ко всей камере. Архив один: HD, если он задан, иначе SD. Отсутствующий вариант потока возвращает 404. Старые адреса `/api/v1/...` и `/snapshots/...` удалены.

## Снимки

GET/HEAD JPEG возвращает `Content-Type: image/jpeg`, `Cache-Control: no-store`, `X-DvorCam-Snapshot-State: live|fallback` и `X-DvorCam-Captured-At` (Unix-секунды). При потере потока или перезапуске возвращается последний сохранённый JPG из `/data/last-frames`; возраст не ограничен. Архивный диск для этих адресов не нужен. Снимок сохраняется на диск не чаще раза в 30 секунд, поэтому это может быть не самый последний кадр перед отключением.

`/status/` возвращает JSON: `live` (есть свежий JPG и heartbeat), `has_image`, `captured_at` (Unix-секунды или null) и `url`. Статус имеет `Cache-Control: no-store`. Для неизвестной камеры/варианта — 404; для известного потока без кадра статус возвращает 200, `has_image: false`. Наличие сохранённого JPG не подтверждает доступность камеры сейчас.

## Запрос архива

Параметры `start`, `end` и `at` — Unix-время **в секундах**, не миллисекундах. Допускаются только конечные числа: `start` должен быть меньше `end`, а `at` — находиться внутри диапазона. Сервер ограничивает диапазон сроком хранения и текущим временем.

Ответ содержит `api_version: 1` и `playback_mode: static_segments`, а также поля:

```text
camera_id, recording_enabled, has_archive, server_time, retention_seconds,
range, time_unit, available_start, available_end, recorded_duration,
intervals, clips, selection, video, preview
```

`clips` — готовые файлы. Для каждого указаны полные `start`, `end`, `duration`, а также `segment_id`, `size_bytes`, `available_start`, `available_end`, `url` и `preview_url`.

`intervals` — участки, доступные в запрошенном диапазоне. Пропуски между записями сохраняются.

Если передан `at`, в `selection` будет выбранная запись, `requested_time`, `playback_time`, `offset_seconds` и `gap_skipped`. Если запрошенное время попало в пропуск, выбирается следующая запись. Если её нет, `selection` равен `null`.

## Воспроизведение

Открывайте `url` из ответа, разрешая относительные адреса от `PUBLIC_URL`. Для выбранного момента используйте `selection.offset_seconds`. Время на таймлайне рассчитывается как `selection.start + player.currentTime`.

Не собирайте адрес файла вручную и не ограничивайте длительность ровно 300 секундами: длина записей может отличаться. Запрос `/video/?time=...&duration=...` не поддерживается и возвращает 400. Сервер отдаёт готовые файлы и не запускает FFmpeg по запросу.

Во время просмотра обновляйте список примерно раз в 30 секунд. `retention_seconds` учитывает индивидуальный срок камеры, а при его отсутствии — общий. Из-за лимита места доступный архив может быть короче `retention_seconds`. Поле `recording_enabled` означает, что запись включена в настройках; оно не гарантирует, что новые файлы поступают.

## Ответы и ошибки

| Ответ | Значение |
| --- | --- |
| 200, `has_archive: false` | Архив пока пуст |
| 400 | Неверные параметры |
| 404 | Камера или файл не найдены |
| 503 | Хранилище или индекс недоступны |

Отсутствующее превью тоже возвращает 404. Это не должно останавливать проигрывание видео.

## Служебный RTSP

При `RTSP_DOCKER_ACCESS=true` соседний доверенный контейнер в Docker-сети DvorCam может читать `rtsp://dvorcam:8554/<id>-hd` или `rtsp://dvorcam:8554/<id>-sd` через RTSP/TCP. Порт не опубликован на хосте. Разрешено только чтение готовых HD/SD-потоков; внешняя публикация и чтение внутренних путей запрещены. По умолчанию доступ из Docker-сети выключен. Подробнее: [настройка RTSP](../README.md#rtsp-для-соседних-контейнеров).
