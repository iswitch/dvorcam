# DvorCam

DvorCam принимает видео с RTSP-камер, показывает его через WebRTC и сохраняет архив в MP4. Видео не перекодируется.

После установки список камер пустой. Камеры добавляются в админке. Мониторинг в комплект не входит.

Исходники: [github.com/iswitch/dvorcam](https://github.com/iswitch/dvorcam).

## Что нужно для установки

- Linux-сервер с Docker Engine и Docker Compose v2. Основная платформа — Ubuntu 24.04.
- Домен, направленный на сервер, и открытые порты: TCP 80/443, UDP и TCP 8189.
- Доступ сервера к камерам по RTSP. Если камеры в другой локальной сети, понадобится VPN или настроенный маршрут.
- Папка для архива. Отдельный диск не нужен.

У камеры один ID и до двух RTSP-адресов: HD и SD. Можно указать только один. Каждый поток должен быть H.264 без B-кадров. Если камера передаёт звук, DvorCam автоматически убирает его из трансляции и архива без перекодирования видео. Отключать звук на камере не нужно.

## Установка из GitHub

Склонируйте проект и создайте файл настроек:

```sh
git clone https://github.com/iswitch/dvorcam.git
cd dvorcam
cp .env.example .env
chmod 600 .env
```

Откройте `.env` и заполните четыре строки:

```dotenv
PUBLIC_URL=https://video.example.ru
ADMIN_USERNAME=admin
ADMIN_PASSWORD='ваш-собственный-длинный-пароль'
ARCHIVE_HOST_PATH=./archive
```

Укажите свой домен, логин и пароль длиной от 12 символов. Кавычки вокруг пароля сохраняют символы `$` и `#`; если в самом пароле есть одинарная кавычка, её нужно экранировать по правилам Compose.

Создайте папку архива (для отдельного диска сначала смонтируйте его), соберите образ и запустите сервис:

```sh
sudo install -d -m 700 -o 1000 -g 1000 ./archive
docker compose -f compose.yaml -f compose.build.yaml build dvorcam
docker compose up -d
# Только после проверки, что нужный архивный диск подключён:
docker compose exec --user 1000:1000 dvorcam python /app/prepare_storage.py
```

Если `ARCHIVE_HOST_PATH` изменён, вместо `./archive` создайте именно эту папку. Подготовка принимает только пустую папку или уже знакомое хранилище.

Для сборки и первого запуска нужен интернет: Docker скачает зависимости и Caddy, а Caddy получит HTTPS-сертификат. Продлеваться сертификат будет автоматически. Браузер загружает оформление админки с Google Fonts и jsDelivr.

Откройте свой адрес https://video.example.ru/admin/ в браузере, войдите и добавьте камеры. Срок хранения и размер архива задаются там же.

**Логин и пароль защищают админку. Видео, снимки и архив доступны по ссылке без входа.** Отдельных пользователей и токенов для просмотра в этой версии нет.

## Где хранится архив

По умолчанию — в папке `archive` рядом с `compose.yaml`. Папку создаёт администратор перед первым запуском. Можно указать другой путь в `ARCHIVE_HOST_PATH`, например `/mnt/video/dvorcam`.

Путь меняется в `.env`; в админке он только показывается. После изменения `.env` выполните `docker compose up -d` — простой перезапуск не применит новые переменные.

Используйте папку только для DvorCam, без символических ссылок. Если она уже существует, дайте пользователю и группе с ID 1000 права на чтение и запись. DvorCam не меняет права существующих файлов рекурсивно.

Чтобы перенести уже накопленный архив:

1. Остановите сервис командой `docker compose stop`.
2. Скопируйте всё содержимое папки в новое место, включая скрытые файлы, с сохранением прав.
3. Измените `ARCHIVE_HOST_PATH` и выполните `docker compose up -d`.
4. Проверьте старые записи и появление новых.

Не удаляйте файл `.dvorcam-storage`: по нему сервис узнаёт свою папку. Если диск недоступен, имеет ошибки записи или вместо него оказалась пустая папка, останавливается запись; live, JPG и админка продолжают работать. Админка показывает предупреждение. Контейнер также может запуститься без подготовленного архива, если сама папка привязки существует. Compose не создаёт отсутствующий путь автоматически.

Настройки, ID камер, служебные файлы и последние сохранённые JPG находятся в Docker-томе `data` (`/data`), отдельно от `ARCHIVE_HOST_PATH` (`/archive`). Держите Docker-том `data` на системном SSD и сохраняйте его резервную копию. `docker compose down -v` удаляет этот том и настройки: не используйте эту команду для обновления или замены диска.

Для замены сломанного диска:

1. Подключите и смонтируйте новый диск средствами ОС. RAID, форматирование и подключение устройств через админку не выполняются.
2. Подготовьте пустую папку DvorCam с правами UID/GID 1000:1000. Убедитесь, что это папка на нужном носителе, а не оставшийся пустой каталог системного диска.
3. Если путь изменился, исправьте `ARCHIVE_HOST_PATH`. После перемонтирования носителя пересоздайте контейнер: `docker compose up -d --force-recreate --no-deps dvorcam`. Docker может сохранять привязку к прежнему mount даже при том же пути на хосте; один `restart` этого не исправляет.
4. Выполните `docker compose exec --user 1000:1000 dvorcam python /app/prepare_storage.py`. Для нового диска эта команда ставит метку текущей установки, не меняет настройки и отказывает для постороннего или непустого немаркированного хранилища.
5. Убедитесь, что предупреждение исчезло и появились новые записи. Сервис повторяет проверку автоматически примерно каждые 3 секунды. Старый архив остаётся на старом диске; автоматического копирования или объединения нет.

Если знакомое хранилище снова доступно внутри контейнера, запись возобновляется автоматически. При физической неисправности с зависшими операциями ввода-вывода время восстановления зависит от ОС и драйвера: приложение не может гарантировать мгновенное отключение зависшего устройства.

## Срок и размер архива

В админке доступны три настройки. По умолчанию:

| Настройка | Значение |
| --- | --- |
| Срок хранения | 1 день |
| Максимальный размер | 100 ГБ |
| Оставлять свободными на диске | 10 ГБ |

Для каждой камеры можно указать свой срок хранения в целых днях (1–3650). Пустое поле наследует общую настройку, включая её дальнейшие изменения. Уменьшение действующего срока камеры, в том числе возврат к более короткому общему сроку, требует подтверждения. Очистка, API, таймлайн и превью используют один и тот же срок камеры. Общие лимит объёма и резерв свободного места действуют на все камеры.

Старые записи удаляются по сроку или при нехватке места. В размер входят все файлы на архивном хранилище: записи, подготовленные MP4, превью и временные файлы. Live JPG и их сохранённые копии хранятся отдельно и в эту квоту не входят. ГБ здесь — 1 000 000 000 байт.

Очистка проверяет архив примерно каждые 30 секунд и начинает освобождать место при 90% заданного размера или приближении к резерву. При 95% либо свободном месте ниже резерва запись приостанавливается. Просмотр камер продолжает работать.

Лимит не удерживается точно до байта: текущая запись и подготовка файлов требуют запаса. Если места мало, архив может храниться меньше указанного срока. При уменьшении срока или размера админка попросит подтвердить удаление старых записей.

Запись появляется в архиве после закрытия файла — до 5 минут плюс время подготовки. FFmpeg копирует видео без перекодирования (`-c copy`). При запросе видео ничего собирать не нужно: сервер отдаёт готовый MP4.

Превью имеют ширину 240 пикселей и сохраняют пропорции кадра. При запуске сервис проверяет превью архива и восстанавливает отсутствующие или повреждённые из готовых записей. Проверка продолжается в фоне во время работы. При нехватке места восстановление приостанавливается. Записанное видео при этом не меняется.

Снимки и превью требуют декодирования кадров и создают дополнительную нагрузку. При потере камеры зритель видит анимацию логотипа и надпись «НЕТ СИГНАЛА»; эта заглушка в архив не записывается. Время в именах новых файлов — UTC, в браузере — местное.

Заглушка — двухсекундный цикл: секунда движения и секунда паузы. Согласованный шаблон со шрифтом Bebas Neue Cyrillic включён в образ (`app/assets/no-signal.mp4`); интернет и отдельная установка шрифта для него не нужны. При добавлении или изменении RTSP-потока FFmpeg создаёт отдельный файл в `/data/fallback/` с разрешением, FPS и профилем H.264 камеры, без B-кадров и звука. Логотип сохраняет пропорции; при другом формате кадра добавляются тёмные поля. Видео камеры по-прежнему не перекодируется.

При запуске новой версии заглушки существующих потоков обновляются один раз по сохранённым параметрам, без подключения к камерам. Содержимое шаблона определяет `fallback_revision` каждого потока. Повторный запуск использует готовые файлы; при ошибке генерации остаётся прежняя заглушка, а следующая попытка выполняется при следующем запуске. Старые MP4 остаются в `/data/fallback/` для отката; перед обновлением сохраняйте копию data volume. Обновление заглушек может увеличить время первого запуска.

## Камеры, группы и адреса

В админке укажите название, HD и/или SD RTSP. Для каждого потока можно отдельно задать логин и пароль. При редактировании текущие значения уже заполнены; для удаления потока есть отдельная галочка.

Камеры можно объединять в группы и искать по названию, ID или группе. Название группы меняется сразу у всех камер в ней. Цветовая тема выбирается вверху страницы и сохраняется в браузере.

Для камеры с ID `entrance`:

| Адрес | Содержимое |
| --- | --- |
| `/entrance-hd/` | Эфир HD |
| `/entrance-sd/` | Эфир SD |
| `/entrance-hd.jpg/` | Снимок HD |
| `/entrance-sd.jpg/` | Снимок SD |
| `/archive/entrance/` | JSON архива |
| `/archive/entrance/preview/?time=...` | Превью архива |
| `/archive/entrance/video/?segment=...` | Готовый фрагмент MP4 |

Если вариант HD или SD не добавлен, его плеер и снимок возвращают 404. В архив пишется HD; если адрес HD не задан — SD. Временная потеря HD не переключает запись на SD. Просмотр архива в браузере доступен из админки.

JPEG создаются только из ключевых кадров, не чаще раза в секунду. При редких ключевых кадрах снимки обновляются реже. Рекомендуемый интервал ключевых кадров на камере — 1–2 секунды. Актуальные снимки лежат в RAM (`tmpfs`, 64 МиБ на контейнер); запись архива от них не зависит. Не чаще раза в 30 секунд для каждого потока сохраняется полный последний JPG на системный диск в `/data/last-frames`. Сохранение атомарное; ошибка сохранения не останавливает RAM JPG. Сохранённый кадр может отставать от эфира примерно на 30 секунд, при редких ключевых кадрах — дольше.

Если JPG старше 30 секунд, поток не поступает более 5 секунд или контейнер перезапущен, JPEG-адрес отдаёт сохранённый кадр с временем съёмки. Он сохраняется до поступления новых кадров; если камера ещё не дала ни одного сохранённого кадра — 404. Плеер показывает «Нет сигнала» и время последнего сохранённого кадра, когда свежего JPG нет; WebRTC показывает анимированную видеозаглушку. JPG и его статус доступны даже без архивного диска. При редких ключевых кадрах нельзя обещать обновление раз в секунду без декодирования остальных кадров.

Полный формат JSON и параметры запросов: [адреса и архив](docs/API.md).

## Подключение WebRTC

Обычно достаточно `PUBLIC_URL`: адрес для WebRTC берётся оттуда. Если видео должно идти с другого адреса, добавьте `WEBRTC_PUBLIC_HOST` — имя хоста или IP без `https://` и порта.

За роутером нужно пробросить UDP и TCP 8189. HTTP-прокси или CDN этот порт не заменяет. Для сетей, блокирующих прямое соединение, может понадобиться TURN; в комплекте его нет.

HLS и остальные способы публичной трансляции отключены. По умолчанию RTSP и управляющий API MediaMTX доступны только внутри контейнера. Браузерный просмотр разрешён с адреса `PUBLIC_URL`.

## RTSP для соседних контейнеров

Другой сервис на том же сервере может читать готовые HD/SD-потоки DvorCam через RTSP/TCP. Видео передаётся без перекодирования и дополнительных подключений к камере.

Доступ выключен по умолчанию. Для включения добавьте в `.env`:

```dotenv
RTSP_DOCKER_ACCESS=true
```

Примените настройку:

```sh
docker compose up -d --no-deps dvorcam
```

Если используете свой reverse proxy, сохраните тот же набор Compose-файлов:

```sh
docker compose -f compose.yaml -f compose.proxy.yaml up -d --no-deps dvorcam
```

Контейнер DvorCam пересоздаётся с коротким перерывом трансляции и записи. Обычный `docker compose restart` не применяет изменения `.env`.

Подключите контейнер клиента к Docker-сети DvorCam. В штатном комплекте она называется `dvorcam_default`. Пример дополнения к существующему Compose-файлу клиента: замените `consumer` именем своего сервиса.

```yaml
services:
  consumer:
    networks:
      - default
      - dvorcam
networks:
  default: {}
  dvorcam:
    external: true
    name: dvorcam_default
```

Если меняли имя Compose-проекта DvorCam, укажите фактическое имя его сети. После подключения используйте адрес нужной камеры и качества:

```text
rtsp://dvorcam:8554/<id>-hd
rtsp://dvorcam:8554/<id>-sd
```

Например, для камеры `entrance` поток HD доступен по `rtsp://dvorcam:8554/entrance-hd`. В клиенте выберите транспорт TCP. Контейнерное имя `dvorcam` доступно в общей Docker-сети; для клиента на другом сервере потребуется отдельное защищённое соединение.

Чтение HD/SD доступно без пароля участникам этой сети, поэтому подключайте к ней только доверенные сервисы. Для соседних контейнеров запрещены публикация видео и чтение внутренних путей `-source`; управляющий API остаётся на localhost.

Порт 8554 не публикуется на хосте. Для этого режима не добавляйте его в `ports` и не открывайте в firewall. Чтобы выключить доступ, установите `RTSP_DOCKER_ACCESS=false` и повторите команду применения: RTSP снова будет доступен только внутри контейнера. Допустимы `true` и `false`; ошибочное или пустое значение останавливает запуск.

## Если HTTPS уже настроен

Можно использовать свой reverse proxy. Если встроенный Caddy уже работает, сначала остановите его:

```sh
docker compose stop gateway
```

Запустите вариант без Caddy:

```sh
docker compose -f compose.yaml -f compose.proxy.yaml up -d
```

Если nginx находится на этом же сервере, больше ничего настраивать не нужно: порты 9001 и 8889 доступны только через `127.0.0.1`.

Если nginx находится на другой машине, добавьте в `.env` LAN-адрес сервера DvorCam:

```dotenv
PROXY_BIND_IP=10.1.1.200
```

После этого используйте ту же команду запуска с `compose.proxy.yaml`. Создавать дополнительный Compose-файл не нужно. В firewall разрешите TCP 9001 и 8889 только с IP машины, на которой работает nginx. Не публикуйте эти порты в интернет.

Пример для nginx: [docker/nginx.conf.example](docker/nginx.conf.example). Замените домен и пути к сертификату своими. Если nginx находится на другой машине, также замените `127.0.0.1` в `proxy_pass` на `PROXY_BIND_IP`. Авторизацию админки проверяет DvorCam.

Настройте свой прокси:

| Адрес на сервере | Пути |
| --- | --- |
| `<адрес DvorCam>:9001` | `/`, `/admin`, `/admin/*`, `/archive/*`, `/static/*`, `/<id>-hd/`, `/<id>-sd/`, `/<id>-hd.jpg/`, `/<id>-sd.jpg/`, `/healthz` |
| `<адрес DvorCam>:8889` | `/<id>-hd/reader.js`, `/<id>-sd/reader.js`, `/<id>-hd/whep`, `/<id>-sd/whep` и дочерние WHEP URL |

Передавайте исходный `Host` и правильный `X-Forwarded-Proto`. Не открывайте `/whip`. Порт 8189 UDP/TCP по-прежнему должен быть доступен напрямую.

## Обслуживание

Посмотреть состояние и последние сообщения:

```sh
docker compose ps
docker compose logs --tail=100 dvorcam
```

Состояние камер, хранилища и записи видно в админке. Логи ограничены тремя файлами по 10 МБ на сервис.

### Проверка памяти

DvorCam постоянно записывает архив, поэтому Linux использует свободную память как файловый кеш. В Proxmox такой кеш может выглядеть как постепенное заполнение памяти, хотя он освобождается при необходимости. Оценивайте состояние по столбцу `available` в `free -h`, а процессы — по `docker stats`:

```sh
free -h
docker stats --no-stream
grep -E 'MemAvailable|Cached|Buffers|Dirty|Writeback|SReclaimable' /proc/meminfo
```

Если сервер действительно перезагрузился или процесс был остановлен из-за памяти, проверьте предыдущую загрузку:

```sh
journalctl -k -b -1 --no-pager | grep -Ei 'out of memory|oom-kill|killed process'
last -x | head -20
```

Большой `buff/cache` при нормальном `available` не является утечкой. Рост `MEM USAGE` самого контейнера или записи OOM в журнале уже требуют диагностики.

Если Proxmox убивает процесс `kvm`, а внутри VM столбец `available` остаётся большим, память закончилась на узле Proxmox. Проверьте запас памяти всех VM, включите ballooning или уменьшите фиксированную память этой VM. Docker и DvorCam не могут вернуть память гипервизору при `balloon: 0`.

**Версии 0.3.x используют новый формат камер. Автоматической миграции из 0.1.0 нет: для перехода нужна новая установка с пустыми настройками и архивом. Сохраните прежнюю установку отдельно для отката.**

Перед обновлением остановите DvorCam и сохраните `.env` и Docker volume `data`.

Если устанавливали из GitHub, получите изменения, пересоберите образ и запустите сервис:

```sh
git pull --ff-only
docker compose -f compose.yaml -f compose.build.yaml build dvorcam
docker compose up -d
```

При внешнем reverse proxy последнюю команду запускайте с тем же дополнительным файлом, который использовали при установке:

```sh
docker compose -f compose.yaml -f compose.proxy.yaml up -d
```

Если устанавливали из готового комплекта, загрузите новый образ и замените файлы выпуска, сохранив свой `.env`. Затем выполните `docker compose up -d`.

Не меняйте имя проекта `dvorcam`: к нему привязаны volumes с настройками и сертификатами.

Для отката сохраните предыдущий образ. Если новый выпуск меняет формат данных, понадобится и сделанная до обновления копия `data`. Резервная копия самого видео делается отдельно.

Не выполняйте `docker compose down -v`: эта команда удаляет настройки и сертификаты. Не передавайте посторонним `.env` и вывод `docker compose config` — в них есть пароль.
