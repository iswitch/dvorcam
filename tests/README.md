# Проверки изменений хранения

## Анимированная заглушка

`tests/test_fallback.py` проверяет настоящее создание и декодирование MP4 для SD 16:9/4:3, портретного потока, HD 1088 строк, дробного FPS и 4K/60 FPS; профиль H.264, отсутствие B-кадров/звука, движение и статичный конец цикла. Также проверяются сохранение через форму камеры, однократное обновление при запуске без доступного RTSP, сохранность старого файла при ошибке и удаление незавершённого MP4.

`tests/native_storage_smoke.py` использует новую заглушку: после потери синтетической камеры читает несколько циклов через настоящий MediaMTX и проверяет неизменность последнего реального JPG.

Локальные тесты используют временные каталоги и синтетическое видео; к production-камерам не подключаются.

```sh
python -m pip install -r requirements.txt pytest
python -m pytest -q
```

Покрыты индивидуальный/унаследованный срок, подтверждение уменьшения, согласованность API/превью/очистки, запуск без архива (нет каталога/метки, чужая метка, ошибка IO), повторная проверка хранилища, сохранность state/storage-id, RAM JPG и постоянный fallback. Отдельный тест с виртуальным временем проверяет не более одного сохранения JPG за 30 секунд, в том числе после перезапуска, и продолжение RAM JPG при ошибке постоянной копии.

Для проверки с настоящим RTSP нужен FFmpeg и официальный MediaMTX **1.21.0** для вашей ОС. Порты loopback 18554, 8554, 9997, 8889, 8189 должны быть свободны:

```sh
MEDIAMTX_BIN=/absolute/path/to/mediamtx python tests/native_storage_smoke.py
```

Тест сам запускает два локальных MediaMTX и FFmpeg, затем останавливает только свои процессы. Проверяет получение JPG, отключение записи при сохранённом live, потерю RTSP, неизменность сохранённого кадра при переходе на NO SIGNAL, запуск без метки архива и без RAM. Логи и тестовые файлы остаются в напечатанном временном каталоге. На macOS `/proc` отсутствует: цикл worker проверяется pytest с подставленным inventory, реальный MediaMTX reload — этим стендом. Это не проверка WebRTC через внешний NAT или физического отказа диска.

Docker-стенд: соберите текущие исходники под тегом `dvorcam:0.3.6`, запустите `tests/compose.smoke.yaml` на **новых тестовых томах**, затем `python tests/smoke.py`. Скрипт явно подготавливает тестовый архив. Дополнительные проверки: `tests/recovery.py`, `tests/variants_smoke.py` с соответствующими Compose-файлами. Не используйте эти скрипты и их операции chown/restart с production-контейнерами.

Проверено 08.10.2026: 63 pytest-теста логики хранения на Linux, 37 целевых проверок после редактуры интерфейса, синтаксис Python/JS и Compose, RTSP-стенд MediaMTX 1.21.0. Отдельный Docker smoke проверил JPG, запись, готовый MP4, HEAD/Range и превью через Caddy; recovery — потерю камеры/метки архива, restart, сохранность JPG и автоматическое восстановление. Физический отказ и перемонтирование нового носителя не имитировались; Docker bind может требовать recreate, как описано в README.
